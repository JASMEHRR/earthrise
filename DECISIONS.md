# Decisions

- 2026-11-24: Now-playing comes from the Spotify Web API (currently-playing + queue), logged in with PKCE so no client secret is stored. Undo: none needed, it is the core feature.
- 2026-11-24: Sound bars use Android's Visualizer on the TV's output mix when Spotify plays on the TV; otherwise a simulated beat. Spotify does not give apps its audio, and its audio-analysis API is closed to new apps. Undo: Settings > TV audio for bars.
- 2026-11-24: Synced lyrics come from LRCLIB (free, no key, CORS open). Songs without synced lyrics show title and artist. Undo: Settings > Lyrics.
- 2026-11-24: Removed the drawn Earth and the part numbers; background is plain black with a soft glow behind the record, per feedback.
- 2026-11-24: APK is built by GitHub Actions (no Java or Android SDK on this PC). Gradle 8.7, AGP 8.5.2, minSdk 23. Undo: build locally with Android Studio.
- 2026-11-24: Release signing key is a PKCS12 file made with OpenSSL, kept in .signing/ (git-ignored) and stored as GitHub secrets, so every build can update the previous install.
- 2026-11-24: Repo is private. Making it public would let the TV download the APK straight from the Releases page. Undo: gh repo edit --visibility public.
- 2026-11-24: Styles use vw/vh and solid text colour (no container units, no gradient-clipped text) so older Android TV WebViews render it.
- 2026-11-24: Six lyric entrance styles (blur, rise, pop, typewriter, karaoke, glitch). Default "Mix per song" picks one per song from a hash of the song id, so a song always keeps its style. Undo: Settings > Lyric animation.
- 2026-11-24: Background scene comes from the first artist's Spotify genres (stars, aurora, bokeh, rain, embers, lasers, neon grid). Spotify's audio-features (mood, tempo) are closed to new apps, so genre is the best signal left. Songs without genres fall back to aurora or stars by album colour. Undo: Settings > Background > None.
- 2026-11-24: Song wheel is collapsed to the corner disc by default and opens on scroll, swipe, arrow or click; choosing a song plays it and folds the wheel back. Skips of up to 5 songs use Next; further picks replay the queue from that song.
- 2026-11-24: Menu is one right-side drawer with Music, Connect (setup steps) and Settings tabs. Library needs three extra Spotify scopes; tokens from before ask the user to reconnect.
- 2026-11-24: Added an Album cover background (blurred, darkened, slow drift) as a Settings option, and a right-side now-playing panel (title, artist, album, time, up next) so the right of the frame is not empty. Hidden on portrait phones. Undo: Settings > Song info / Background.
- 2026-11-26: New "Singer" background uses the artist photo from the same Spotify artist lookup as the genres, so it costs no extra calls. The photo sits left of the record behind the big lyrics and fades out to the right, so the small song-info text keeps a clean dark background. Undo: Settings > Background.
- 2026-11-26: New "Music video" background plays the song's YouTube video muted under the canvas and keeps it at Spotify's position (re-seeks past 1.5 s of drift, hides during adverts or stalls). Spotify's own Canvas loops have no public API. Finding videos needs a free YouTube Data API key (web: pasted in Connect; TV app: GitHub secret YOUTUBE_API_KEY). Searches cost 100 of the 10,000 free daily units, so about 100 new songs a day; results are cached per song and a search waits until a song has played 1.5 s. Undo: Settings > Background.
- 2026-11-26: Label music videos refuse to play (error 150) when the page runs on localhost or 127.0.0.1, but the same Kesariya videos played when the page was served from the TV app's own address (https://appassets.androidplatform.net, simulated in Edge). So the web preview on this PC mostly falls back to the album cover; the TV app is the real target. The app still tries up to 5 results before falling back.
- 2026-11-26: Accepted risk: Android exposes the EarthriseNative bridge to every frame, including the YouTube player, so YouTube's scripts could read the Client ID and YouTube key (both already readable from the APK) or toggle TV audio for bars. Moving to an origin-checked WebMessageListener would close it. Undo: Settings > Background off the Music video.
- 2026-11-26: Video choice: one extra videos.list call (1 unit) reads each result's length, shape and title. Vertical clips and anything under a minute are dropped; the rest are ranked by closeness to the Spotify track length, a bonus for "official video", penalties for live, lyric, audio, cover and behind-the-scenes uploads, and a bigger penalty when the title lacks the song name. Checked on Lover (Diljit Dosanjh) and Blinding Lights: both pick the official music video.
- 2026-11-26: The YouTube key lives in the existing Google Cloud project "My First Project" (the account is at its project limit), restricted to YouTube Data API v3 only, named "Earthrise YouTube". Stored in .env (git-ignored) and as the GitHub secret YOUTUBE_API_KEY. Undo: delete the key under APIs & Services > Credentials.
- 2026-11-26: TV side of Earthrise Link. "Connect Spotify" on the TV opens Connect and finds the laptop (UDP broadcast to 5198, or a typed address), pairs with a 4-digit code approved on the laptop, then takes short-lived tokens from GET /link/token instead of logging in on the TV. The laptop's plain-http calls run in Java (LinkClient, private addresses and /link/ paths only) because the page is https; the app allows cleartext for that (usesCleartextTraffic). The on-TV Spotify login stays in the Connect tab as a fallback. Undo: Connect tab, Stop using the laptop.
- 2026-11-26: Cut the gimmicks, per feedback ("it's gimmicky, the changing backdrop"). Backdrop no longer changes per song by genre: lasers, neon grid, embers, bokeh, rain and "Match the music" are gone; choices are Album cover (default), Singer, Music video, Stars, Aurora, None. Lyrics use one style for every song: Rise (default), Blur, Karaoke, Typewriter (Mix per song, Pop and Glitch are gone). Old saved choices fall back to the defaults. Bright covers are darkened more so lyrics stay readable. Undo: git revert this commit.
- 2026-11-26: Remote fixes in the menu. Every Spotify poll (2-3 s) rebuilt the Settings buttons, so the focused button vanished and the next arrow jumped back to the first tab: you could never reach Background. Now polls only update the background note, and any menu redraw puts focus back on the same button. Menu key opens Settings (as the README said). The menu is a third of a TV screen (min(480px, max(340px, 36vw))) instead of half.
- 2026-11-26: Lyric style "Rotate" is back as the default, per feedback ("make everything auto rotate"): each song gets one of the calm styles (Rise, Blur, Karaoke, Typewriter), the same one every time. The backdrop stays fixed (album cover) since its per-song switching felt gimmicky. Control bar is smaller (44/50px buttons instead of 56/64px). Speed on the Fire TV: the canvas now draws at 1x there (the WebView reports 2x, so it was 1920x1080 every frame) and the record's glowing rim is drawn once instead of with a live shadowBlur each frame: median frame 109ms -> 19ms. While paused or idle it draws at about 15 fps.
- 2026-11-27: Laptop pairing is one-time (contract v2). On Allow, Earthrise Link hands the TV the full Spotify login (refresh token included) and forgets it, so the laptop app can be closed for good; the TV renews the login with Spotify itself using the same baked-in Client ID. The laptop does not keep a copy because Spotify may rotate refresh tokens and two holders would log each other out. Pairing a second TV means logging in on the laptop again (one click). Undo: older v1 kept the login on the laptop and needed it running.
- 2026-11-27: TV side of link v2. When pairing is approved the TV takes the Spotify login from the reply (access and refresh token) and renews it straight with Spotify from then on, so the laptop is needed once only. Links saved by older versions are dropped at start (Connect shows again). An older laptop app that answers without "spotify" still works through the token path until the TV restarts.
- 2026-11-27: All playlists: /me/playlists is paged (50 at a time, up to 500; it fetched only the first 30) and new logins ask for playlist-read-collaborative (not added to LIBRARY_SCOPES, so older logins are not forced to reconnect). The song wheel chooses what to play: Left / Right switch Up next, Your playlists, Liked songs and Recently played; OK plays the item (playlist as context, liked songs from that one on). The wheel opens on Up next again each time. "Play X on Spotify" from Jarvis in Glass Home opens Earthrise with extra "play": your own playlist by that name first, else Spotify's best matching song (or playlist when the words say playlist), on the active device or the first one Spotify lists.
- 2026-11-27: Music menu: a search box (outside the part that redraws, so the TV keyboard stays open), playlists open to their songs (pick any song, Play all, Shuffle), and All liked songs pages through up to 2,000. Jarvis requests use the same paths: "X from my Y playlist", "my liked songs", "X from liked songs", "album X", "songs by X", "X by Y", "shuffle ..." and "search X" (opens results). Playlist songs are read from /items with a /tracks fallback, since Spotify renamed it. Checked against a fake Spotify in Edge: every request sends the expected play body. Not yet checked against real Spotify on the TV.
- 2026-11-27: Checked on the TV with the real Spotify: songs of playlists someone else made come back 403 for this app (Spotify's development-mode rule; 10 of the user's 22 playlists). The playlist view now says so and keeps Play all and Shuffle (playing a playlist still works), and Jarvis's "play X from <someone else's playlist>" plays the playlist instead of failing. Your own playlists list their songs as before.
- 2026-11-28: On the TV, play and resume go to the TV's own Spotify app (name Fire TV/AFT*, else type TV), waking it for 4 s if asleep, instead of whatever device Spotify last used (a stale Chrome web player swallowed songs). Undo: drop tvDevice() from startPlayback and control.
